# HWP / HWPX 뷰어 앱 — 개발 계획

> 목표: 브라우저에서 `.hwp`(한글 5.x 바이너리)와 `.hwpx`(OWPML XML) 문서를 열어
> 텍스트와 기본 서식을 보여주는 웹 앱. 파일은 서버로 전송하지 않고
> **100% 클라이언트(브라우저 안)에서 파싱** — 개인정보/보안 걱정 없이 사용 가능.

## 1. 왜 웹 앱인가

- 이 레포의 기존 스택(Vite + React + TypeScript + Tailwind + PWA)을 그대로 재사용할 수 있다.
- 설치 없이 링크 하나로 배포(GitHub Pages/Netlify 워크플로가 이미 있음).
- PWA로 만들면 오프라인에서도 동작 → 사실상 로컬 앱처럼 사용 가능.
- 파싱이 전부 JS/TS로 가능하다(아래 포맷 분석 참고). 네이티브 코드 불필요.

## 2. 두 포맷의 구조 (조사 요약)

### HWPX — 쉬운 쪽부터
- 정체: **ZIP 컨테이너 + XML**(OWPML, KS X 6101 국가표준). DOCX와 비슷한 구조.
- 내부 구조:
  - `mimetype`, `version.xml`, `META-INF/container.xml`
  - `Contents/header.xml` — 글꼴, 문자/문단 모양 정의(스타일 테이블)
  - `Contents/section0.xml`, `section1.xml`… — 본문 (문단 `<hp:p>`, 런 `<hp:run>`, 텍스트 `<hp:t>`, 표 `<hp:tbl>`, 그림 `<hp:pic>`)
  - `BinData/` — 삽입 이미지 원본
  - `Preview/PrvText.txt` — 미리보기용 순수 텍스트(디버깅/폴백에 유용)
- 파싱 방법: `fflate`(또는 JSZip)로 ZIP 해제 → 브라우저 내장 `DOMParser`로 XML 파싱.
  외부 파서 라이브러리 없이 자체 구현 가능. **난이도 낮음.**

### HWP 5.x — 어려운 쪽
- 정체: **MS CFB(OLE 복합 문서) 컨테이너 + 바이너리 레코드 스트림.**
  한컴이 스펙 문서("한글 문서 파일 형식 5.0")를 공개해 둠.
- 내부 구조:
  - `FileHeader` (256바이트): 시그니처 `HWP Document File`, 버전, 속성 플래그
    (압축 여부, 암호화 여부, **배포용 문서 여부**)
  - `DocInfo`: 글꼴/모양 정의 레코드 스트림 (플래그에 따라 raw-deflate 압축)
  - `BodyText/Section0…N`: 본문 레코드 스트림 (역시 압축)
  - `BinData/`: 이미지 등 바이너리
  - `PrvText`: UTF-16LE 미리보기 텍스트 (**최후 폴백으로 매우 유용**)
- 레코드 구조: 4바이트 헤더 = TagID(10bit) + Level(10bit) + Size(12bit, 0xFFF이면 확장 4바이트).
  본문 텍스트는 `HWPTAG_PARA_TEXT` 레코드의 UTF-16LE + 제어문자(0~31, 일부는 8바이트 확장).
- 파싱 방법: `cfb`(SheetJS, CFB 리더) + `fflate`(raw inflate) 조합으로 자체 구현하거나,
  기존 오픈소스 **hwp.js(hahnlee, Apache-2.0)** 를 파서 코어로 활용/참고. **난이도 중상.**

### 공통 주의사항
- **암호화 문서 / 배포용(DRM) 문서**는 열 수 없음 → 감지해서 친절한 에러 메시지를 보여준다.
- 한글(HWP)의 레이아웃을 100% 재현하는 건 목표가 아님. "내용을 읽을 수 있는 뷰어"가 목표.

## 3. 아키텍처

```
src/
  parser/              # UI와 완전히 분리된 순수 TS 파서 (테스트 대상)
    model.ts           # 공통 문서 모델: Document > Section > Paragraph > Run(+표/이미지)
    hwpx/              # ZIP+XML 파서 → 공통 모델
    hwp/               # CFB+레코드 파서 → 공통 모델
    detect.ts          # 매직바이트로 포맷 자동 감지 (ZIP=PK, CFB=D0CF11E0)
  viewer/              # React 렌더링 계층
    DropZone.tsx       # 드래그&드롭 + 파일 선택
    DocumentView.tsx   # 공통 모델 → HTML 렌더
    Toolbar.tsx        # 확대/축소, 검색, 내보내기
  workers/
    parse.worker.ts    # 큰 파일도 UI 안 멈추게 Web Worker에서 파싱
```

핵심 설계 원칙: **두 파서가 하나의 공통 문서 모델로 수렴**하고, 렌더러는 모델만 안다.
포맷별 차이는 `parser/` 안에서 끝낸다.

## 4. 마일스톤

### M0 — 프로젝트 골격 (반나절)
- 이 레포에 뷰어 앱 골격 추가(기존 게임과의 공존 방식은 착수 시 결정 — 아래 §6).
- 의존성: `fflate`, `cfb`. 파일 드롭 → 포맷 감지 → "인식했음"까지.

### M1 — HWPX 텍스트 뷰어 (1~2일) ← 첫 번째로 동작하는 결과물
- ZIP 해제, `section*.xml` 파싱 → 문단/런 텍스트 추출 → 화면 렌더.
- `header.xml`에서 굵게/기울임/크기 등 기본 문자 서식 매핑.
- 실패 시 `Preview/PrvText.txt` 폴백.

### M2 — HWP 5.x 지원 (3~5일, 가장 큰 덩어리)
- `FileHeader` 파싱 → 압축/암호화/배포용 플래그 판정.
- `cfb` + raw inflate로 `BodyText/Section*` 레코드 스트림 순회, `PARA_TEXT` 추출.
- 1차 목표는 텍스트만. 서식(CHAR_SHAPE 매핑)은 2차.
- 막히면 폴백 순서: `PrvText` 스트림 → hwp.js 파서 코어 도입 검토.

### M3 — 서식·표·이미지 (1주)
- 두 포맷 모두: 표 렌더링, `BinData` 이미지 표시(Blob URL), 문단 정렬/여백.
- 페이지 구분 표시(완전한 페이지네이션은 비목표, 구분선 정도).

### M4 — 앱 완성도 (며칠)
- 문서 내 검색, 확대/축소, 다크 모드.
- 내보내기: 텍스트(.txt), HTML 복사, (선택) 인쇄→PDF.
- PWA: 오프라인 캐시, "연결 프로그램"처럼 파일 열기(File Handling API, 지원 브라우저 한정).
- 여러 파일 탭 전환.

## 5. 테스트 전략

- 파서는 순수 함수이므로 **Vitest 골든 테스트**: `fixtures/`에 샘플 .hwp/.hwpx를 두고
  "추출된 텍스트/구조 스냅샷"과 비교.
- 샘플 확보: 한컴오피스 뷰어/한글로 직접 만든 간단 문서 + 공공기관 공개 서식
  (정부24, 각 부처 고시 서식 등 공개 HWP가 풍부함).
- 에러 케이스 픽스처: 암호화 문서, 배포용 문서, 손상된 ZIP, HWP 3.x(옛 포맷, 미지원 안내).

## 6. 착수 시 결정할 것 (기본안 포함)

| 결정 | 기본안 |
|---|---|
| 기존 게임(rule-smith)과 공존? | 이 레포 그대로 두고 뷰어를 새 폴더/새 레포로 분리하는 것을 권장. 간단히 가려면 이 레포를 뷰어 앱으로 전환해도 됨(게임은 브랜치에 보존) |
| HWP 파서 자체 구현 vs hwp.js | **자체 구현 우선**(텍스트 추출까지는 스펙이 감당 가능), hwp.js는 참고 구현·폴백 |
| 렌더 방식 | HTML/CSS 흐름 렌더(검색·복사·접근성 유리). 캔버스 정밀 렌더는 비목표 |

## 7. 리스크

- **HWP 5.x 스펙의 방대함** → 텍스트 우선, 서식은 점진 확장으로 범위 통제.
- **배포용/암호화 문서** → 기술적으로 미지원이 정답. 명확한 안내 UI로 처리.
- **레이아웃 정확도 기대치** → "한글 대체"가 아니라 "읽기용 뷰어"임을 UI에서 명시.
- **테스트 샘플 저작권** → 직접 생성한 문서와 공공 서식만 레포에 포함.
